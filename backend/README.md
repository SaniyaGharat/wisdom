# AI-Powered Client–Supplier Matchmaking Platform

Welcome to the **AI-Powered Client–Supplier Matchmaking Platform**.

This platform pairs B2B client requirements with qualified supplier offerings by combining dense **transformer-based semantic similarity** with multi-attribute **deterministic business rule scoring**, automated **in-app notifications**, **dashboard aggregation APIs**, and a hardened, developer-friendly REST API.

---

## 📐 API Conventions & Response Standards (Phase 4)

All API endpoints follow strict, consistent response structures designed for frontend integration (e.g. React, Next.js, Lovable, Bolt.new).

### 1. Consistent Pagination Envelope
All listing endpoints (`/api/clients`, `/api/suppliers`, `/api/matches`, `/api/notifications`) return a standardized paginated envelope:

```json
{
  "items": [ ... ],
  "total": 128,
  "limit": 20,
  "offset": 0,
  "has_more": true
}
```

- **`limit` cap**: Minimum `1`, maximum `100`. Requests with `limit > 100` are rejected with `422 Unprocessable Entity`.
- **`offset`**: 0-indexed starting position.
- **`has_more`**: Boolean flag calculated as `(offset + items.length) < total`, simplifying infinite scroll and pagination UI controls.

---

### 2. Standard Error Response Shape
All error responses (400, 404, 422, 500) return a uniform error object:

```json
{
  "error": "Validation Error",
  "detail": "Request payload or query parameter validation failed",
  "status_code": 422,
  "errors": [
    {
      "field": "quantity_required",
      "message": "Input should be greater than 0",
      "type": "greater_than"
    },
    {
      "field": "budget",
      "message": "Input should be greater than or equal to 0",
      "type": "greater_than_equal"
    }
  ]
}
```

- **404 Not Found**: Triggered when a requested UUID entity (`client_id`, `supplier_id`, `match_id`, `notification_id`) does not exist.
- **422 Unprocessable Entity**: Triggered on invalid query parameters or request body fields with granular, field-level diagnostics.
- **500 Internal Server Error**: Catches unhandled server exceptions, logs full stack traces server-side, and returns a safe JSON error payload without leaking internal tracebacks.

---

### 3. Diagnostic Health Check (`GET /api/health`)
Returns real-time status of both database connectivity and the SentenceTransformers AI model:

```json
{
  "status": "ok",
  "version": "4.0.0",
  "environment": "development",
  "database": "connected",
  "embedding_model": "loaded"
}
```

## 🧠 AI Matching Approach (Hybrid Engine)

### Why Hybrid Scoring Over Pure Keyword/String Matching?
In real-world B2B procurement and supply chain matchmaking:
1. **Lexical & Semantic Gaps**: Pure keyword search fails when clients and suppliers use different industry terminology (e.g. *"Flexible OLED display modules"* vs *"AMOLED screens with integrated touch ICs"*, or *"Custom PCB fabrication"* vs *"SMD circuit board assembly"*). Dense neural embeddings capture deep domain equivalence and intent.
2. **Commercial & Operational Feasibility**: High semantic relevance alone is insufficient. A supplier with a perfect product description cannot fulfill an order if their price is 3x the client's budget, if their lead time is 60 days instead of 14 days, or if they have insufficient supply volume.

Therefore, this platform implements a **hybrid multi-layer evaluation**:

$$\text{Final Score} = (\text{Semantic} \times 0.35) + (\text{Category} \times 0.20) + (\text{Location} \times 0.15) + (\text{Quantity} \times 0.10) + (\text{Budget} \times 0.10) + (\text{Delivery} \times 0.10)$$

The composite score is scaled from **0 to 100** and stored alongside a human-readable justification (`match_reason`) and individual sub-scores for complete explainability.

---

### Weight Breakdown & Sub-Scorers

| Component | Weight | Scoring Logic |
|---|:---:|---|
| **Semantic Similarity** | **35%** | Cosine similarity between 384-dimensional dense vectors generated by `all-MiniLM-L6-v2` (`sentence-transformers`). Cached in-memory with SHA-256 keys. |
| **Category Alignment** | **20%** | `1.0` if categories match exactly (case-insensitive), else `0.0`. |
| **Location Proximity** | **15%** | `1.0` if exact city/metro match, `0.5` if regional / state / country alignment, else `0.0`. |
| **Quantity Capacity** | **10%** | `1.0` if $\text{Available} \ge \text{Required}$; else linear ratio $\frac{\text{Available}}{\text{Required}}$ capped at `1.0`. |
| **Budget Feasibility** | **10%** | `1.0` if $(\text{Unit Price} \times \text{Required}) \le \text{Budget}$; else linear decay penalty based on overage percentage (floored at `0.0`). |
| **Delivery Timeline** | **10%** | Heuristic regex parser extracting days; `1.0` if supplier lead time $\le$ client timeline; decaying penalty up to $1.5\times$; else `0.0`. |

*All weights and thresholds are configurable in `backend/app/config.py`.*

## 🔔 Notifications & Dashboard Endpoints

### Notification System & Provider Architecture
Notifications are stored in the database (`Notification` model) and dispatched automatically whenever a new match meeting the threshold ($\ge 40$) is detected.

The service uses a **Provider Pattern** (`BaseNotificationProvider` in `app/services/notification_service.py`). Swapping or extending in-app notifications with external email (SendGrid) or SMS (Twilio) services simply requires implementing `send(...)` and registering the provider via `register_provider(...)` without modifying the core matching engine.

## 🛠 Tech Stack

- **Python**: 3.11+ (Python 3.13 tested)
- **AI/ML**: `sentence-transformers` (`all-MiniLM-L6-v2`), `scikit-learn`, `numpy`
- **Framework**: [FastAPI](https://fastapi.tiangolo.com/) (OpenAPI / Swagger / ReDoc)
- **Database**: [PostgreSQL](https://www.postgresql.org/) (SQLite in-memory for unit tests)
- **ORM**: [SQLAlchemy 2.0](https://docs.sqlalchemy.org/en/20/)
- **Migrations**: [Alembic](https://alembic.sqlalchemy.org/)
- **Validation**: [Pydantic v2](https://docs.pydantic.dev/latest/) & `pydantic-settings`
- **Testing**: [pytest](https://docs.pytest.org/) & `httpx`
- **Containerization**: Docker & Docker Compose

## 💻 Local Development Setup

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1       # On Windows (or 'source .venv/bin/activate' on Linux/macOS)
pip install -r requirements.txt

# Apply database migrations
alembic upgrade head

# Seed data & run matchmaking + notifications
python -m app.seed.seed_data

# Run tests
pytest -v

# Start development server
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```
